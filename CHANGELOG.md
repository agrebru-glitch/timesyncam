# История изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [семантические](https://semver.org/lang/ru/).

## [Не выпущено]

### Исправлено

- **Дорожки из папок «001», «002»** брали имя папки съёмки выше — у двух камер выходило одно и то же имя. Папки из одних цифр больше не считаются служебными (служебные папки карт — номер с буквами: 100MSDCF, 100GOPRO). Если имя всё же занято другой дорожкой, к нему добавляется номер.

## [0.4.0-beta.6] — бета для тестеров, не выпущена

Правила слабого совпадения из бет 4–5 проверены не только на одном матче, а на синтетических съёмках того же рода: камера из 30–45 коротких клипов со сбоями тайм-кода и «трансляция», где звук площадки тихий (15–35%), а поверх него громкий посторонний. Найденные слабые места исправлены в самом алгоритме.

### Исправлено

- **Кандидаты сдвига — и голосованием клипов.** Сравнение записей целиком тонет в постороннем звуке: верный сдвиг не попадал и в шесть лучших. Теперь двадцать самых длинных клипов ищутся каждый по всей другой записи, и сдвиг, на который независимо указали три клипа, становится кандидатом.
- **Проверка по клипам — честной проверкой на случайность.** Вместо «больше половины клипов на месте» — вероятность набрать столько попаданий случайно (меньше одной десятитысячной). Короткие клипы при слабом звуке часто не находят себя, но семь попаданий из девятнадцати случайно не бывают.
- **Сбои тайм-кода до ±20 с** учитываются: клип ищется в ±60 с, попадание засчитывается в ±20 с, проверка на случайность — под это окно.
- **Сбои тайм-кода разбираются при любом найденном совпадении**, а не только при слабом; участок с другим сдвигом признаётся по двум согласным клипам подряд.
- Совместный поиск участка между долгими паузами не перекрывает сбой, уже найденный внутри него, и не сбивается одиночным ложным пиком.

Итог на синтетике: реалистичные сбои (до 2,5 с на долгих паузах) — 10 из 12 съёмок без единого клипа мимо, в двух звук площадки самый тихий (16–19%) — совпадение не найдено; без общего звука — ни одного ложного совпадения из 24. Сбои до ±20 с через каждые несколько клипов — 3 из 12 полностью; такое на съёмке не встречается.

## [0.4.0-beta.5] — бета для тестеров, не выпущена

### Исправлено

- **Конец съёмки после долгой паузы.** Клипы между двумя долгими паузами (камеру выключали — тайм-код между ними непрерывен) теперь ищутся и вместе, одним длинным окном. На матче последние клипы после паузы 83 с стояли на 2 с мимо: трансляция почти кончилась, поодиночке они совпадали слабо, и участок получал сдвиг предыдущего. Теперь, если свои клипы участка и совместный поиск согласно показывают другое место, участок встаёт по ним.

## [0.4.0-beta.4] — бета для тестеров, не выпущена

Проверка на футбольном матче: камера Sony со 170 короткими клипами и трансляция с голосами комментаторов.

### Исправлено

- **Слабое, но настоящее совпадение больше не отбрасывается молча.** Программа сразу нашла верный сдвиг трансляции, но подтвердить его окнами по 20 с не смогла: у камеры из сотни коротких клипов окна попадают в паузы и на стыки, а в трансляции поверх звука стадиона — комментаторы. Теперь, если окна не подтвердили, каждый длинный клип ищется сам в ±30 с вокруг места: случайно в ±1 с он попадает с вероятностью около 3%, поэтому пять и больше попаданий из большинства клипов — не случайность (на матче — 14 из 19, у соперника 3).
- **Сбои тайм-кода камеры при слабом общем звуке.** После выключения камера пересчитывает тайм-код по часам; на матче клипы со 79-й минуты стояли на 0,38 с, со 101-й — на 2,2 с мимо. Каждый клип ищется отдельно, ряд их сдвигов делится на участки с постоянным сдвигом — ступенька засчитывается, только если её подтверждают несколько клипов подряд; одиночные ложные пики остаются выбросами. О сбое — сообщение в «Замечаниях».

## [0.4.0-beta.3] — бета для тестеров, не выпущена

Проверка чтения метаданных на настоящих файлах: камера Sony без XML рядом с клипом, телефон Android, папка рекордера с копиями PluralEyes.

### Исправлено

- **Растянутые копии записей больше не попадают в сверку как отдельные записи.** Выравнивание хода часов делает копии той же записи, растянутые во времени: PluralEyes кладёт их в подпапку `pluraleyes_drift_corrected` прямо в папке рекордера, а сама программа — рядом с XML. Программа обходит папку целиком и брала такую копию лишней записью. На съёмке тестера копия PluralEyes попала в дорожку H5, и программа решила, что часы H5 спешат на 261 ppm, — та же ложная коррекция, что у PluralEyes. Теперь растянутая копия узнаётся как копия: то же начало записи, та же длина с точностью до 0,1 %, имя продолжает имя оригинала или в истории обработки BWF на шаг больше. В сверку идёт оригинал, о копии — строка в «Замечаниях». Дорожки многоканального рекордера одной длины копиями не считаются.

- **Звук телефона, который в файле начинается позже видео.** Часть телефонов (так пишет realme) записывает звук с задержкой около 0,2 с и отмечает это в файле — монтажка ставит звук туда же. Программа читала звук целиком с первого сэмпла, а куски для точной сверки — от начала файла. Эти два разбора расходились на 0,2 с, и клип телефона мог встать на 6–7 кадров мимо. Теперь весь звук отсчитывается от начала клипа, как в монтажке.
- **Камера Sony без XML рядом с клипом.** Sony кладёт тот же XML и внутрь самого MP4. Если XML рядом потерялся или клип переименовали, программа берёт его оттуда: тайм-код с пометкой drop frame, время с часовым поясом, частоту замедленной съёмки (S&Q), модель, объектив и гамму. На съёмке с A7 IV вложенный XML совпал с XML рядом у всех 301 клипа.
- **Время в именах файлов Pixel (`PXL_…`) — по UTC.** Программа читала его как местное. Важно, только если в самом файле даты нет.
- **Телефон Android узнаётся по метке системы в файле, а не только по имени** (`VID_…`, `PXL_…`). Телефон Sony Xperia теперь тоже Android, а не камера Sony. Модель берётся из файла, если телефон её пишет. Таймлапс и замедленная съёмка на Android помечаются, как S&Q у Sony.

### Добавлено

- **На таймлинии видно, какие записи при экспорте заменит выровненная копия.** Такая запись заштрихована по нижнему краю, в подписи — имя копии: «ZOOM0001.WAV → ZOOM0001_drift-0.150s.wav». В карточке дорожки — на сколько спешат или отстают часы. Оригиналы не меняются, копии лежат рядом с XML в папке «<имя XML> — выровненный звук».
- **Программа сама определяет, что значит время в файле — начало записи или конец.** Одни телефоны пишут момент начала (realme), другие — момент остановки (так устроен стандартный модуль записи Android). Программа сверяет время в файле со временем в имени файла. Если имени со временем нет — с записями того же устройства, совпавшими по звуку. Запись без общего звука встаёт с учётом своей длины, во вкладке «Замечания» — пояснение.
- **В расширенном отчёте — устройство каждого файла MP4/MOV** (`<файл>.boxes.json`): где камера хранит время, тайм-код и метаданные. По нему можно разобрать незнакомую камеру без видео. Если рядом с клипом Sony XML не было, в отчёт кладётся вложенный (`<файл>.nrtm.xml`).

### Изменено

- **В расширенном отчёте нет координат съёмки и серийных номеров камер.** Телефоны пишут координаты в сведения о файле — теперь они убраны. Серийный номер заменён условным: две камеры одной модели по-прежнему различаются, но сам номер не восстановить.

## [0.4.0-beta.2] — бета для тестеров, не выпущена

Стресс-проверка на съёмке тестера: те же звук и сведения о файлах, но файлы переименованы, даты сбиты, XML потеряны, дорожки добавлены в другом порядке.

### Исправлено

- **Тайм-код, выставленный по часам самой камеры или рекордера, больше не держит место вопреки звуку.** Это те же часы, только точные до кадра: две камеры с часами, разошедшимися на 3 с, так и стояли на 3 с врозь, а рекордер с верной датой и сбитым временем суток уводил всю съёмку на 10 часов. Теперь решает звук. Тайм-код держит место жёстко, если в карточке камеры он отмечен точным или звук подтвердил, что он общий у двух устройств (совпал до 0,1 с), — тогда дальняя камера не сдвигается на путь звука.
- **Время суток не зависит от порядка дорожек.** Когда у всех устройств свои часы, берутся часы средней из камер, расходящихся на минуты. Раньше выбор зависел от того, какую дорожку добавили первой (разница до полутора минут).
- **Камера Sony без XML.** Тайм-код 29,97 в MP4 записан без пометки drop frame, читался как NDF и к вечеру уходил от часов на секунды: камера распадалась на отрезки, половина концерта вставала на 50 с мимо. Теперь DF или NDF выбирается по согласию с часами камеры.
- **Даты файлов сбились при копировании, а тайм-код цел.** Раньше такие даты рвали тайм-код устройства на отрезки: два файла рекордера переставали быть одной записью, у камер вторая половина концерта уезжала на полтора часа. Теперь при времени только из дат файлов паузы между клипами берутся из тайм-кода. Клип, у которого тайм-код переходит через полночь, больше не уезжает на сутки.
- **Даты копирования не решают, когда была съёмка.** Если по датам файлов записи устройства накладываются друг на друга, это время копирования: такое устройство о дате не голосует и встаёт по звуку. Раньше три камеры с датой копирования перевешивали петличку с верным временем, и вся съёмка уезжала на двое суток.
- **Часть съёмки, не связанная по звуку с остальной,** встаёт по ошибке часов тех же камер в остальной съёмке, а не по часам другой камеры. Если общих камер нет и она встала по своим часам, об этом есть предупреждение.
- **Записи рекордера с датами файлов, сбитыми при копировании** (по ним записи накладываются друг на друга): запись без общего звука встаёт встык к соседней. Раньше она вставала по дате копирования — на 6 минут мимо и без предупреждения. О каждой записи, поставленной без звука и без верной даты, теперь есть предупреждение.

- **Выравнивание хода часов работает на настоящем звуке.** На съёмке тестера ни одна выровненная копия не проходила проверку, и в XML молча шли оригиналы. Проверка была слишком строгой не в том: требовала совпасть с конкретной камерой до 8 мс, а запись по звуку стоит по согласию всех камер, и у видео свои часы. Теперь копия годится, если расхождение с одной и той же камерой постоянно по всей длине (допуск растёт с расстоянием между точками); отражение у микрофона не мешает, места проверяются по 8 с, в каждом пробуются до трёх камер. Файл без общего звука с камерами (продолжение разрезанной записи) принимается, если проверена копия соседнего файла того же устройства. На съёмке тестера выровнены все 6 записей: у петлички расхождение с камерой по длине файла — 2 мс вместо 19.
- **Выровненные копии — по папкам дорожек** («<имя XML> — выровненный звук/<дорожка>/»): у двух рекордеров или двух карт одной петлички имена файлов совпадают, раньше копии затирали друг друга. Папки с оригиналами программа не трогает. Если копию не удалось сделать или проверить, окно экспорта говорит почему.
- **Порядок дорожек больше не влияет на раскладку.** В четырёх из 32 вариантов стресс-проверки (звук добавлен первым, дорожки вперемешку) клип камеры уходил на 37 мс.
- **Сбой тайм-кода камеры после паузы находится от 25 мс** (было 60): на съёмке тестера CAM 01 после антракта сбилась на 37 мс, и клип вставал то по звуку, то по тайм-коду.
- **BWF-время целыми секундами не считается тайм-кодом.** Оно случайно совпадало с тайм-кодом камеры до 0,1 с, программа принимала их за общий генератор и переставала уточнять рекордер — второй файл вставал на 0,15 с мимо.
- **Большие съёмки:** точки сверки по волне распределяются поровну — сначала по одной на каждый клип, потом следующие. Раньше на сотне клипов лимит съедали пары с хорошим звуком, а клипы со слабым оставались без точной сверки.
- Клип камеры без общего звука с другими записями — в «Стоит проверить», если у этой камеры звук уже нашёл сбой тайм-кода после паузы: тогда и такой клип мог встать мимо. Иначе — для сведения.
- **Запись рекордера, разрезанная на файлы по 2 ГБ:** второй файл встаёт ровно с конца первого. Раньше он вставал по времени в BWF, а оно записано целыми секундами: на концерте тестера вторая часть записи рекордера опаздывала почти на секунду.
- **Точная сверка по волне стала намного плотнее:** точки — вдоль всего клипа (до 12 на клип), а не только там, где совпал отпечаток громкости; фон для оценки пика — по широкому окну; отражение у самого микрофона (4–6 мс) больше не выбрасывает точку. На съёмке тестера точек стало 47 вместо 9, и нашёлся сбой тайм-кода камеры после паузы на 70 мс, который раньше списывался на ход часов рекордера.
- **Ход часов петлички, пишущей файлами по 30 минут,** измеряется по всей записи, а не по одному файлу, и не обнуляется, если измерен точно. Ноль у одной записи больше не переписывает ход другой.
- **Клипы, поставленные по звуку, больше не подвигаются вплотную к соседу.** Файлы петлички с ходом часов наползают друг на друга на десятки миллисекунд — раньше программа «исправляла» это, и вся петличка вставала по первому файлу. В XML при таком наложении укорачивается хвост предыдущего клипа, место следующего не меняется.

### Добавлено

- **Уточнение каждого клипа по звуку.** После сборки по записям каждый клип сверяется по звуку со всеми, кто звучит одновременно с ним, а места всех клипов решаются вместе. Тайм-код, сбившийся после выключения камеры на доли секунды, секунды BWF-времени рекордера и ложное «встык» по часам теперь находятся по звуку — на концерте тестера это вторые половины трёх камер (0,3–0,4 с), клип на 2 с и файл рекордера на 0,4 с. Запись не рвётся от шума измерений: связь внутри устройства держится, пока звук не покажет явный сбой.
- **Ход часов звуковых устройств измеряется по звуку** — по всей длине записи, с погрешностью. Двигает клипы, только если измерен надёжно.
- **Выравнивание хода часов при экспорте** (окно экспорта, включено по умолчанию; какие записи выравнивать, решает программа): рядом с XML создаются растянутые копии звука, начало и BWF-время — как у оригинала. Каждая копия проверяется по звуку с камерами; не прошедшая проверку удаляется, в XML остаётся оригинал. В отличие от PluralEyes, запись с ходом часов в пределах кадра не растягивается.
- **Погрешность синхронизации** у каждой камеры и рекордера — в карточке («точность ±4 мс»); хуже кадра — предупреждение. Эхо зала распознаётся: точка, где отражение почти так же сильно, как прямой звук, не принимается за точную. Расстояние до сцены по звуку не видно (звук идёт около 3 мс на метр) — для картинки дальних камер точнее контрольный кадр.
- **Папки — в проекте монтажки, как у PluralEyes.** В XML для Premiere — корзина на каждую дорожку, клипы из разных подпапок — во вложенных корзинах. В FCPXML для DaVinci — ключевые слова с именем папки: корзины из FCPXML DaVinci не переносит, но по ключевым словам сам собирает смарт-корзины (Media Pool → Smart Bins → Keywords).
- **Несколько камер в одной папке** (три камеры с одной карты): каждая камера на своей дорожке, их одновременные клипы не считаются ошибкой «накладываются». Клип после смены карты встаёт на дорожку своей камеры.
- `scripts/stress-report.mts` — стресс-проверка по расширенному отчёту: переименования, сбитые даты, потерянные XML, порядок дорожек и клипов.

### Изменено — интерфейс (по отзыву тестера)

- **Дорожки прокручиваются**: колёсиком над названиями или Alt + колёсико над таймлинией; новая дорожка сразу видна, строка «+ Камера + Звук» больше не уезжает под строку состояния.
- **Карточка камеры — коротко**: имя, «модель · клипы · длительность» и одна строка итога («Встала по звуку · точность ±4 мс»). Подробности и настройки тайм-кода — по «Подробнее». Объектив, частота кадров и разрешение убраны: по ходу съёмки они меняются и о камере ничего не говорят. Ручной сдвиг камеры из карточки убран — точно подгонять удобнее в монтажке; сдвиг на целые часы и сутки по-прежнему предлагают кнопки в «Замечаниях».
- **Значок камеры или наушников — в цвете дорожки** (в карточке, на таймлинии и в предпросмотре) вместо отдельной цветной точки: вид записи и её цвет — в одном знаке.
- **«Ошибки» → «Замечания»**: сначала то, что мешает точной стыковке, потом «Стоит проверить», в конце «Для сведения» (свёрнуто); внутри — по камерам. Число на вкладке — только то, что стоит открыть.

## [0.4.0-beta.1] — бета для тестеров, не выпущена

Переработана логика синхронизации — по отзывам бета-тестеров (концерт: три камеры, рекордер с датой 2010 года, петличка кусками).

### Изменено

- **Сверка по звуку — все дорожки со всеми.** Каждая пара записей сравнивается по всей длине, без опоры на часы, и каждый найденный сдвиг проверяется окнами по всей общей части. Сдвиги всех пар должны сходиться по кругу; противоречия разрешаются в пользу более подтверждённых. Раньше сверка шла цепочкой от одной опорной камеры: если опора стояла неверно или совпадение в повторяющейся музыке было ложным, ошибка расходилась на всех.
- **Повторяющаяся музыка.** Если звук почти одинаково совпадает в нескольких местах, лучший сдвиг должен выиграть очно — на тех же местах записи. Если не выигрывает, программа не угадывает и прямо говорит, что звук похож на несколько мест.
- **Согласие дат.** Время съёмки определяет большинство устройств. Устройство с датой далеко от остальных (рекордер с невыставленными часами, 2010 год) не становится опорой и не растягивает таймлинию на годы — его место находит звук.
- **Время суток** для сведённых по звуку камер — по самой большой компании устройств с согласными часами, а не по середине между всеми.
- **Запись кусками** (петличка по 30 минут, файлы рекордера, главы GoPro) сверяется как одна запись: кусок без общего звука встаёт вместе с остальными.
- **Ход часов рекордера** за длинную запись: запись встаёт по своей середине.
- Время читается из имени файла вида «18-52-06.wav» (день — из даты файла).
- Сверка идёт в фоновом потоке: окно не замирает, сверку можно остановить. Линейка таймлинии выдерживает любой разброс времени.
- XML для Premiere: звук камеры — стереодорожкой, а не двумя моно.
- Дорожки называются по папкам («CAM 01»), у них значки камеры или наушников и сведения «2 клипа · 29,97 к/с · стерео». Кнопки «Камера» и «Звук». Окна выбора открываются в последней папке.
- Меню синхронизации — значками. Сообщения о часах: «Часы X спешат на 3 с относительно остальных камер».

### Добавлено

- **Расширенный отчёт** («Ошибки» → «Сохранить расширенный отчёт»): архив со звуком клипов без видео, сведениями о файлах, решениями программы и сведениями о системе — для разбора съёмки разработчиком.

## [0.3.6] — 2026-10-30

### Добавлено

- Клипы раскладываются по дорожкам своих камер. При синхронизации программа смотрит, какой камерой снят каждый файл (модель и серийный номер из метаданных), и если в папку одной камеры попал файл другой — переносит его на дорожку той камеры: там он встаёт по её часам, тайм-коду и звуку и в монтажке оказывается на её дорожке. Отметка контрольного кадра на клипе едет вместе с ним. Файлы на диске не трогаются; что и куда перенесено — в «Ошибках». Это первый шаг к автоматическому распределению камер по дорожкам.

### Исправлено

- Копия клипа другой камеры в папке камеры (например, без XML) больше не ломает синхронизацию. Раньше копия приносила чужие часы и тайм-код: камера получала лишний отрезок («тайм-код сбивался»), сверка по звуку цеплялась за копию, а настоящие клипы камеры оставались на месте своих часов — иногда в часах от остальных. Теперь копия находится сама и убирается с таймлинии — на дорожке остаётся один экземпляр файла, с XML. Так же — если одна запись лежит в двух папках одной камеры. Копией считается только тот же файл: совпадают размер до байта, длина, частота, кадр, кодек, тайм-код начала и серийный номер камеры. Одноимённые записи разных камер (C0003.MP4 есть у каждой Sony) копиями не считаются.
- Клип своей камеры, у которого потерялся XML, не уезжает на дорожку другой камеры той же модели: без серийного номера программа не угадывает.

## [0.3.5] — 2026-10-29

### Исправлено

- Камера, которую сверка по звуку не нашла с первого раза, теперь сверяется ещё раз, когда встанут остальные камеры. Раньше результат зависел от порядка дорожек: камеру сверяли, пока камер, с которыми у неё общий звук, ещё не было на местах, и она оставалась по своим часам. У камеры без тайм-кода (и с Rec Run) каждый клип тогда стоял со своей ошибкой часов до секунды, и сдвиг всей дорожки в монтажке исправлял только одно место. Повторы идут, пока встают новые камеры, — так находятся и камеры, которые слышат друг друга по цепочке.
- Сдвиг, найденный одним случайным совпадением и не подтверждённый звуком рядом, больше не считается окончательным: такая камера тоже сверяется ещё раз.

### Изменено

- Камера без тайм-кода, которую не нашёл обычный поиск, ищется подробнее: пробы во всех её клипах каждые 20 секунд. Хватит одного уверенно найденного места (его должны подтвердить хотя бы две пробы и звук рядом) — по нему встанет вся камера, а дальше каждый клип уточнится по своему звуку. Клипы, которые сразу не зацепились, сверяются ещё по нескольким местам и с двумя камерами.
- Клип камеры без тайм-кода, у которого нет своего общего звука, подтягивают соседи до и после: между двумя зацепившимися клипами поправка идёт по времени от одного к другому. Раньше он брал поправку только предыдущего клипа.
- Общий звук вокруг клипа ищется в пределах ±30 секунд, а не ±10.
- Полоса на кнопке «Синхронизировать» не откатывается и тогда, когда подробный поиск или повторная сверка добавляют работы.
- Окно экспорта: «Для какой монтажки». По умолчанию — DaVinci Resolve (FCPXML): звук каждого клипа там стерео одной дорожкой. Для Premiere Pro — XML; в нём каждый канал звука на своей дорожке, так устроен формат.
- FCPXML: звук каждой камеры ложится в DaVinci в том же порядке, что и её видео. Клипы в файле теперь идут по дорожкам — рекордер, потом камеры сверху вниз, — а не по времени: DaVinci раскладывает звук по дорожкам в том порядке, в каком встречает клипы.
- Подсказка для камеры без тайм-кода, которую не нашёл звук: сдвинуть камеру примерно по хлопку в её карточке и синхронизировать ещё раз.

- Камеры без тайм-кода сверяются по звуку после камер с тайм-кодом, а их клипы, которые не подтвердил ни звук, ни экран синхронизации, больше не служат образцом для других камер — раньше из-за них камеры могли съехать на десятые доли секунды.
- У окна и на панели задач — значок TimesynCam, в том числе при запуске без установки.

## [0.2.0] — 2026-10-29

### Добавлено

- Сверка по звуку — вспомогательный шаг после раскладки по тайм-коду и часам. По кнопке «Синхронизировать» выбирается режим «Тайм-код + звук» (по умолчанию) или «Только тайм-код».
- Точки зацепки по ходу съёмки: точка задаёт поправку для своего клипа и всех следующих, следующая точка сверяет кадр и при расхождении меняет поправку со своего клипа, не трогая предыдущие.
- Защита от случайных совпадений: точка, которая требует большого скачка без подтверждения, отбрасывается.
- Для камер без тайм-кода — своя поправка у каждого клипа с общим звуком.
- Широкий поиск: камера со сбитыми часами или неверным часовым поясом находится по звуку во всей записи других камер.
- Камеры с точным тайм-кодом по звуку только сверяются; о расхождении программа сообщает (камеры могли стоять далеко).
- Распознавание тишины в звуке: прямое предупреждение, если микрофон камеры был выключен.
- Волна звука внутри клипов на таймлинии — чтобы сравнивать камеры глазами. Логарифмическая шкала, кнопка «Волна» для скрытия.
- В мультивью у камеры только со звуком (рекордер) — надпись «Только звук» и полупрозрачная волна вокруг курсора вместо видео.
- Меню по правой кнопке на клипе: удалить с таймлинии (файл на диске остаётся), показать файл в папке. Клавиша Delete удаляет выделенный клип.
- Строка «Звук» в карточке камеры, галочка «Поправлять по звуку», точки сверки на таймлинии, раздел «Сверка по звуку» в справке.
- Демо-съёмка с общим звуком площадки и пятой камерой с неверным часовым поясом.

- Камера могла остаться в состоянии «Читаю…» после окончания чтения папки, и синхронизация не запускалась.

## [0.1.0] — 2026-10-29

Первая версия.

### Добавлено

- Дорожка на каждую камеру: папку камеры можно перетащить на дорожку или выбрать через окно. Несколько папок одной камеры складываются на одну дорожку.
- Чтение времени и тайм-кода: Sony XML, дорожки тайм-кода MP4/MOV/MXF, BWF у рекордеров, время в именах файлов DJI и телефонов, особенности GoPro и DJI.
- Синхронизация тремя способами: точный тайм-код, тайм-код + часы камеры, только часы. Камеры с точным тайм-кодом становятся опорными.
- Учёт перехода тайм-кода через полночь, смешанных частот кадров (25/50/100p, 29,97 drop frame) и сбоев тайм-кода внутри камеры.
- Ручной сдвиг всех клипов камеры по кадру и по секунде.
- Вкладка «Ошибки»: клипы S&Q (красные на таймлинии, убираются кнопкой), наложение клипов одной камеры, нечитаемые файлы, подсказки про часовой пояс и опорную камеру.
- Мультивью и режим одной камеры; прокси Sony, GoPro, DJI и из папки Proxy; стоп-кадры через FFmpeg для остальных клипов.
- Экспорт таймлинии в Final Cut Pro 7 XML для DaVinci Resolve и Premiere Pro. Экспорт доступен только после синхронизации.
- Вкладка «Настройка камер» со справкой по Sony и другим камерам.
- Установщик и архив для Windows 10 и 11 с FFmpeg (LGPL) внутри.
- Демо-съёмка для проверки без своих клипов (`npm run demo`).
